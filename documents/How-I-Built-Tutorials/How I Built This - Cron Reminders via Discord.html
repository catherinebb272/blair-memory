How I Built This

Cron Reminders via Discord (Updated April 2026)

Project Scope

Set up automated reminders that send Discord DMs at scheduled times throughout the day. These can be daily vitamin reminders, pool maintenance checks, or any recurring task that needs a gentle nudge.

Tools Needed

  • OpenClaw CLI - Via your agent or terminal
  • Your Discord User ID - To find this:
    • Open Discord Settings → Advanced → Enable Developer Mode
    • Right-click on your username in any chat → "Copy User ID"
    • It's a long number like 881612027863375872

⚠️ Important: This is the WORKING method (April 2026)

After extensive testing, we found that the isolated session approach doesn't work for Discord DMs. The working approach uses main session + system-event. This tutorial reflects that.

The Working Setup

Here's the only method that reliably sends Discord DMs:

Session: Main

Use the main session because it has full Discord access. Isolated sessions cannot send Discord DMs (they get "Unknown Channel" errors).

Payload: System Event

Use --system-event (not --message) when targeting main session. This wakes the main session with your prompt as a system event.

Delivery: None

Don't rely on the delivery system — the system event itself contains the instruction to send a DM.

Plain English Prompts

Just tell me what you need. Here's what works:

Daily Reminder (e.g., vitamins at 9am)

Tell me: "Set up a daily cron job to send me a Discord DM at 9am Chicago time saying 'Take your vitamins'"

Multiple Times Per Day (e.g., pool skimmers at 1pm, 3pm, 5pm)

Tell me: "Create a cron job to remind me to check the pool skimmers at 1pm, 3pm, 5pm, and 7pm Chicago time""

Every X Minutes (e.g., keepalive every 15 minutes)

Tell me: "Set up a keepalive cron that runs every 15 minutes to send a Discord DM with 'keepalive' and then delete it"

I already know your Discord user ID from your profile, so you don't need to provide it each time.

What I Need From You

  • When: Time(s) you want the reminder (e.g., "9am daily" or "2pm and 4pm")
  • What: The message you want in the DM
  • Where: Your timezone (default is Chicago/America Central)

That's it. I'll figure out the cron expression and set it up.

CLI Reference (For Reference)

openclaw cron add --name "your-job-name" --cron "0 9 * * *" --tz "America/Chicago" --session main --system-event "Send a Discord DM to user YOUR_USER_ID with your message here"

Examples That Work

Daily Vitamins Reminder (9am Chicago)
openclaw cron add --name "daily-vitamins" --cron "0 9 * * *" --tz "America/Chicago" --session main --system-event "Send a Discord DM to user 881612027863375872 with message: Take your vitamins 💊"
Pool Skimmer Reminder (1pm, 3pm, 5pm, 7pm Chicago)
openclaw cron add --name "pool-skimmer-reminder" --cron "0 13-20/2 * * *" --tz "America/Chicago" --session main --system-event "Send a Discord DM to user 881612027863375872 with message: Hey! Go check the pool skimmers"

The Heartbeat Issue

⚠️ Container Restart Issues

Cron jobs can get disabled after a container restart. They show as "skipped" with error "disabled".

Fix: Run openclaw cron list and re-enable any disabled crons with openclaw cron enable JOB_ID

Prevention: Cron jobs are backed up to GitHub nightly. Use bash restore-crons.sh after a restart to restore from backup.

Why This Works

  • Main session has full Discord access and can send DMs
  • System event bypasses the normal conversation flow and directly delivers your prompt
  • No delivery mode needed because the prompt itself contains the DM send instruction

What Doesn't Work (Don't Try These)

  • Isolated session + message tool — Gets "Unknown Channel" error. Isolated sessions can't access Discord DMs.
  • Isolated session + exec tool — Gets "exec host not allowed" error unless you change config.
  • Main session + --message — Requires heartbeat to be enabled, otherwise gets skipped.

Testing Your Cron Job

To test immediately without waiting for the schedule:

openclaw cron run YOUR_JOB_ID

Then check the logs:

openclaw logs | grep -i "Sent via"

Checking Status

openclaw cron list

Shows all cron jobs. Look for "idle" (scheduled), "running" (executing), or "ok" (completed successfully).

Cron Expression Reference

ExpressionMeaning
0 9 * * *9am daily
0 9 * * 1-59am weekdays
0 13-20/2 * * *1pm, 3pm, 5pm, 7pm (every 2 hours from 1-8pm)
0 9,12,18 * * *9am, noon, 6pm daily
*/10 * * * *Every 10 minutes

Backup & Restore

Cron jobs are stored in /home/openclaw/.openclaw/cron/jobs.json. They can be lost if the container is recreated (e.g., during an OpenClaw update).

📦 Backup

Cron jobs are included in the nightly backup to GitHub (file: cron-jobs-backup.json). This runs automatically at 2am UTC.

🔄 Restore

If cron jobs disappear after a container restart, run:

bash /home/openclaw/.openclaw/workspace/restore-crons.sh

Or ask your agent to "restore cron jobs".

Key Takeaways

  1. Main session + system-event — This is the working combination
  2. Heartbeat must be enabled on main or crons get skipped
  3. Test with cron run before waiting for schedule
  4. Backups happen nightly — restore script available if needed
  5. After container restart — Check that crons are still enabled, may need to re-enable
