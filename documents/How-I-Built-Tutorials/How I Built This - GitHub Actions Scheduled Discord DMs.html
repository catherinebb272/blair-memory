GitHub Actions: Reminders Using Discord DMs

Project Scope

Set up automated Discord DM reminders using GitHub Actions as the scheduler instead of cron. This solves the problem of container restarts disabling cron jobs or heartbeat unpredicatability — GitHub Actions runs reliably in the cloud and don't depend on your local setup. And there's no problem with Discord having to "wake up" first.

The workflow fires at scheduled times, runs a small Node.js script that sends a Discord DM, then exits. No server host required. This project assumes you have an existing personal server and agent bot in Discord. See tutorial on Discord at thedenheyron.com

Tools & Info Needed

  • GitHub Account — For creating the repo and Actions
  • New private GitHub Repository — Name it something like "project-pinger"
  • Discord Bot Token — Get from your records or ask your agent to supply it from memory :

Workflow

  1. GitHub Actions scheduler — Fires at cron times (e.g., 1pm, 3pm, 5pm, 7pm Central) Don't forget the time zone!
  2. Node script runs — Each time, it creates a fresh DM channel and sends the message - no Discord "stale channel" issue
  3. Discord API — Uses bot token to create DM and send message, then exits

💡 Why This Approach?

Unlike cron running on a container that can restart and disable jobs or relies on unpredicatable heartbeat, GitHub Actions runs on GitHub's infrastructure. It's free for personal use and reliable. It can still have a 1-2 minute delay from the scheduled time.

Setting It Up Manually

  1. Create private GitHub repo (e.g., "project-pinger")
  2. Add these files package.json, send.js,.github/workflow/send.yml(see code sections below)
  3. In the new repository, go to Settings → Secrets and variables → Actions to add your tokens
  4. Add two repository secrets (make sure to copy exactly):
    • DISCORD_TOKEN — Paste your bot token
    • USER_ID — Paste Your Discord user ID
    • Don't forget to SAVE!

Testing Manually

In your new GitHub repo that contains these files:

  1. Go to the Actions tab in the top menu
  2. Click on "Send Scheduled DM"
  3. Click Run workflow (dropdown → main branch)
  4. Check your Discord DMs — you should get the message within a minute
  5. Talk with your agent if you need help finding sections

Code Files

Create package.json in new Github and paste code

{ "name": "discord-dm-sender", "version": "1.0.0", "dependencies": { "node-fetch": "^2.6.7" } }

Create send.js in Github and paste code:

const TOKEN = process.env.DISCORD_TOKEN; const USER_ID = process.env.USER_ID; // Use native fetch (Node 18+), fallback to node-fetch for older versions const fetch = globalThis.fetch || require("node-fetch"); async function sendDM() { try { // Step 1: Open (or fetch) DM channel const channelRes = await fetch("https://discord.com/api/v10/users/@me/channels", { method: "POST", headers: { "Authorization": `Bot ${TOKEN}`, "Content-Type": "application/json" }, body: JSON.stringify({ recipient_id: USER_ID }) }); const channelData = await channelRes.json(); if (!channelData.id) { console.error("Failed to create DM channel:", channelData); process.exit(1); } console.log("DM channel created:", channelData.id); // Step 2: Send message const messageRes = await fetch( `https://discord.com/api/v10/channels/${channelData.id}/messages`, { method: "POST", headers: { "Authorization": `Bot ${TOKEN}`, "Content-Type": "application/json" }, body: JSON.stringify({ content: "⏰ Scheduled DM check-in. Still alive and behaving." }) } ); const messageData = await messageRes.json(); if (!messageData.id) { console.error("Failed to send message:", messageData); process.exit(1); } console.log("Message sent successfully:", messageData.id); } catch (err) { console.error("Error:", err); process.exit(1); } } sendDM();

Create file .github/workflows/send.yml and paste code:

name: Send Scheduled DM on: schedule: # 1pm, 3pm, 5pm, 7pm Central Time - cron: '0 18,20,22,12 * * *' workflow_dispatch: jobs: send: runs-on: ubuntu-latest steps: - uses: actions/checkout@v3 - name: Install dependencies run: npm install - name: Run DM script run: node send.js env: DISCORD_TOKEN: ${{ secrets.DISCORD_TOKEN }} USER_ID: ${{ secrets.USER_ID }}

Common Pitfalls

⚠️ Things to Watch For

  • UTC vs. Local Time — GitHub cron uses UTC. Convert your desired times properly.
  • Bot Prefix — Must use "Bot " in the Authorization header (with the space).
  • Wrong User ID — Must be YOUR user ID, not the bot's.
  • Bot hasn't DM'd you — The bot needs to have opened a DM with you at least once (the script handles this each run).

Key Takeaways

  1. Free and reliable — GitHub Actions is free for personal repos, runs on their infrastructure
  2. No server maintenance — Unlike container cron, this doesn't depend on your VPS
  3. 1-2 minute delay — Actions may not fire exactly on time, give it a minute buffer
  4. Secrets stay secret — Token and user ID stored in GitHub secrets, not in code
  5. Easy to test — Run workflow manually from the Actions tab
