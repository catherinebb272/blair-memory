# 2026-06-17

## 04:00 UTC — Nightly backup fix

**Incident:** Nightly backup to `catherinebb272/blair-memory` silently failed from **2026-06-10 → 2026-06-16** (7 missed nights).

**Root cause:** A local-only change to `backup-script.sh` added `exec >> /var/log/blair-backup.log`, but `/var/log/` is owned by root and not writable by the `openclaw` user (no `sudo` available in this container). The `exec` ran before anything else, so the script aborted immediately with no log, no commit, no push. The cron ran nightly but produced nothing.

**Last good backup:** `ce2f293` on 2026-06-09. Eight days of workspace changes were uncommitted to blair-memory (still safely in local main, just not in the backup repo).

**Fix applied:**
- Changed `LOG_FILE` from `/var/log/blair-backup.log` to `<workspace>/logs/blair-backup.log`
- Added `mkdir -p` for the logs dir
- Added `logs/` to `.gitignore` so the log itself doesn't get backed up
- Updated `TOOLS.md` "Last verified" line

**Recovery:** Ran script manually. Captured 7 files / 400 insertions / 32 deletions, pushed as commit `72d7920`. Remote and local now in sync.

**Lesson:** When adding a log path to a cron script, sanity-check writability from the cron's user *before* deploying. A self-contained script that can't log is silent when it fails. Also: any change that goes into the workspace but never gets pushed (because the push fails) creates a misleading "verified" line in TOOLS.md — consider adding a heartbeat check that verifies `origin/main` matches `HEAD` after each backup.
